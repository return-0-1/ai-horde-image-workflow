# AI Horde 图像生成工作流 - 完整需求文档

## 1. 项目背景与目标

### 1.1 背景

用户希望构建一个基于 [AI Horde](https://stablehorde.net/) 分布式算力网络的智能图像生成工作流，能够接收任意文字输入，自动匹配 LoRA，生成图像，并支持多轮确认与修改。

### 1.2 目标

构建一个**文字驱动 → LoRA 自动匹配 → 参数生成 → 图像生成 → 结果确认/修改**的完整工作流系统。

---

## 2. 核心功能需求

### 2.1 输入解析

- 接收用户任意文字输入（小说片段、口述描述、角色介绍等）。
- 若输入包含多个场景，默认提取**最后一个场景**作为生成目标。
- 若输入无明显场景，由 AI **自行编造一个合理场景**。
- 使用 `AI绘画提示词工程师（NSFW_漫画）V0.2 提示词模板辅助 LLM 提取场景。

### 2.2 提示词准备

- 整合 `prompt/AI绘画提示词工程师（NSFW_漫画）V0.2.txt` 等专业提示词，该提示词用于生成最终提示词，包括正向和反向。
- 补充用于 **LoRA 检索** 和 **参数决策** 的额外提示词。

### 2.3 LoRA 匹配

- **白名单优先**：AI 在可配置的 LoRA 白名单中查找匹配 LoRA。
- 匹配依据：名称、关键词、描述等元数据。
- **自动搜索（V0.2）**：白名单无匹配时，自动从 CivitAI 搜索 LoRA，经 LLM 审核兼容性后使用。
  - 并行搜索 3-5 个关键概念
  - 按 base model 预筛 + 黑名单过滤
  - LLM 审核通过后按优先级截断（默认 2 个）
- 匹配后调用 CivitAI API 获取 LoRA 介绍、触发词、基础模型等元数据。

### 2.4 生成输出

- AI 结合用户文字、LoRA 介绍、现有提示词规则，输出：
  - **最终提示词**（英文提示词分为正向和反向）
  - **各项生成参数**（模型、尺寸、步数、CFG Scale、采样器、LoRA 强度等）
- 输出格式为 JSON，便于外部系统或 CLI 处理。

### 2.5 图像生成与下载

- 通过 AI Horde API 提交异步图像生成请求。
- 提交后**每 10 秒轮询**一次任务状态。
- 任务完成后自动下载图片到指定文件夹（默认 `output/`）。
- 生成过程记录详细日志（`workflow.log`、`ai_horde_client.log`）。

---

## 5. 非功能性需求

### 5.1 外部 API 对接

- 系统需对接 AI Horde API 进行 LoRA 查询和图像生成。
- 对接 CivitAI API 获取 LoRA 元数据。

### 5.4 日志输出

- 使用 Python `logging` 模块。
- 输出到控制台和文件。
- 关键操作（请求提交、状态轮询、下载完成）均需记录。

### 5.5 错误处理

- CivitAI API 超时或不可用时，不影响核心生成功能。
- AI Horde API 失败时返回清晰错误信息。
- LoRA 验证失败时跳过该 LoRA 或提示用户。

### 5.6 扩展性

- 工作流、客户端、配置管理、GUI 模块职责分离。
- 新增采样器、模型预设、LoRA 时无需修改核心代码。
